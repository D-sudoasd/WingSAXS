# JAC 实验数据与独立用户验证协议

## 当前证据状态

本协议把真实实验验证与软件可用性证据分开记录。当前 checkout 有合成序列和二维 FFT 验证说明，也有 `preflight`、盲标包和人工拟合导出的代码合同；我未找到已提交的真实实验数据包、完成的真实数据 preflight 报告、轨迹人工比对结果或独立用户使用记录。因此，本协议中的主实验序列、独立数据集和两次用户会话均明确保持 `pending`。这些空项不代表阴性结果，也不能写成方法已验证。

JAC 的 Computer Programs 栏目要求说明程序目的、策略、语言、机器要求、输入和输出，并解释软件的新颖性与科学背景；该栏目通常还要求软件实用性及文档充分性由至少两名独立用户成功使用来证明。[JAC 作者指南，§2.7](https://journals.iucr.org/j/services/notesforauthors.html) 本协议将两名用户的操作记录作为待收集证据，不把开发者、自动化测试或 AI 代理当作独立用户。

## 研究对象与冻结流程

验证目标是判断真实二维 SAXS 强度图及其序列中的蝴蝶轨迹、环峰位置和可辨识的图样参数，能否在缺瓣、遮挡、峰重叠和信噪比变化时重复测量；对于随时间、温度或应变的变化，还要检验该变化是否大于重复测量离散程度。结果只支持二维图样测量时，应限于这些可观测量，不据此推断唯一的三维层片结构。

每个数据集分析前冻结 WingSAXS 版本、输入帧清单、PONI、mask、背景处理、强度校正、q 范围、轨迹提取方法、拟合边界、初值策略、重采样设置和导出配置。主要序列用于说明完整分析过程；独立数据集应来自不同样品、测量批次或几何条件，并采用已经冻结的流程。不得依据独立数据逐帧调整参数后再把它称作盲验证。遇到必须人工调整的帧，应保留原始输出、操作记录、调整理由和重跑结果。

采集时保存每帧原始强度、帧顺序和时间/温度/应变等状态变量。另保存样品与制备记录、仪器和探测器信息、曝光时间、波长、样品到探测器距离、像素尺寸、束心、PONI、mask、背景图或背景估计记录，以及校正步骤及其执行位置。记录哪些校正已烘焙进二维强度、哪些由 WingSAXS 或外部流程执行、哪些未执行。所有原始输入保持只读；分析结果写入独立目录。对每个输入和派生记录保存 SHA-256，以便检查证据是否绑定到实际文件。

物理 q 只在 PONI 几何、嵌入式 q 映射或其他明确标定来源及其单位经过核对后报告。若 q 已换算为 `nm^-1`，注明原始单位和换算依据；几何或单位尚未确认时记录 `pixel-q` 或 `unknown`，不报告物理周期。`q*`、`L = 2π/q*`、椭圆轴比和轴角分开列示；轴比或轴角在可见弧段不足时应标为不可辨识或条件估计，不以有限拟合值代替可辨识性证据。

## 两个真实数据集

`examples/validation/jac_experimental_validation_template.json` 是待填写的机器可读证据清单，包含一个主要实验序列和一个独立数据集。开始分析前，两项状态都保持 `pending`。每个序列应逐帧列明路径、帧标识、采集时间或状态变量、曝光和 SHA-256；另外提供帧清单、PONI 或嵌入式 q 映射等实际标定来源、mask、校准核对记录、背景处理来源、校正记录、软件导出和分析配置。

主要序列应覆盖一次完整的原位拉伸、加热或退火过程，保留低信号、遮挡和拟合失败帧。独立数据集用相同冻结流程分析，报告成功、候选、失败和缺失帧的数量及逐帧原因。使用哪种处理条件、数据量和困难帧，应在查看比较结果前写入清单或预注册记录。

### 重复测量

在结构状态不变的条件下采集重复曝光或独立重复测量，记录重复组的帧 ID、曝光条件和状态变量。不得把存在真实时间、温度或应变变化的相邻帧当作重复测量。至少对重复组报告可测参数的组内标准差、成对绝对差的中位数和第 95 百分位，并给出每项统计的重复数及有效帧数。可以报告 `q*`、轴比和轴角，但只对实际可辨识的参数作重复性解释。阈值应依据探测器分辨率、重复测量离散程度和目标研究要区分的变化幅度事先确定，不在本协议中臆定通用百分比门槛。

### 人工轨迹比较

至少由两名未参与算法开发的标注者在不知道 WingSAXS 拟合结果的条件下描绘同一组帧的可见轨迹；若改用同一专家的重复描迹，应记录两次日期、间隔和盲化方式，并将其标为较低层级证据。保留每名标注者的原始点、有效角域、共识轨迹、坐标定义、标注软件与版本、时间戳和输入图像哈希。可复用项目已有的 `annotation-pack` 生成不带拟合覆盖层的人工标注材料，但其 8 帧共识只构成人工参照的一部分，不能替代完整真实序列和独立用户测试。

本项目建议在双方实际观测到的共同弧段内比较人工共识轨迹与软件轨迹，报告双向最近邻距离的中位数和第 95 百分位，并按帧、瓣和信号质量分层。几何已核实时用同一物理 q 坐标；只有 detector 像素坐标可用时，应明确标为像素距离，不换算成物理 q。另对双方均可辨识的 `q*`、轴比和轴角报告差值及有效样本数。角度差按椭圆轴的 180° 周期处理。没有共同支持或参数不可辨识的帧应标为缺失/不可评估并给出分母，不能把外推弧段或拟合失败写成零误差。建议使用两名独立标注者；若由同一专家重复描迹，记录日期和盲化方式，并将其作为较低层级的人工参照。该标注者数量是本项目的验证设计，不是 JAC 作者指南规定。

将软件重采样区间与重复测量或人工参照差异比较时，报告区间覆盖率、区间宽度和可评估样本数。标定误差敏感性分析应明确扰动了哪些校准量及其来源，并报告 q 位置和物理周期的响应。不能只用重采样次数或有限区间本身宣称不确定度已校准。

## 两名独立用户的复现

由两名未参与开发、未共同编写分析步骤的研究者分别执行任务。只提供公开安装和用户文档、固定的软件版本和相同的公开输入包；除非用户任务本身要求，不向其解释具体操作。每人单独完成安装与启动、载入标定和 mask、执行单帧分析、分析连续序列并导出结果。记录操作系统、Python 与 WingSAXS 版本、安装方式、输入包哈希、起止时间、各任务是否完成、求助或人工干预、错误文本以及导出文件哈希。不得把两人共同排错后的同一份成功结果计作两次独立成功。

模板使用匿名 `session_id`，不收集不必要的姓名或联系方式。由协调者依据原始操作记录填写人工审核结果；脚本只核对清单中有路径的文件是否存在及其哈希，不判定用户是否独立，也不判定成功。

## 清单审计与解释边界

在数据路径和哈希填入副本后，可运行：

```powershell
py -3.13 scripts/audit_jac_validation_manifest.py `
  examples/validation/jac_experimental_validation_template.json `
  --base-dir <数据与证据文件的共同根目录> `
  --output results/validation/jac_manifest_audit.json
```

省略 `--base-dir` 时，相对路径按清单所在目录解析；也可在清单文件引用中使用绝对路径。审计报告列出待填元数据、空路径、文件存在性和可选 SHA-256 比对。返回码 `0` 表示没有待补字段、未完成状态或文件引用错误；它仍不表示拟合准确、重复性合格、人工一致或用户成功。返回码 `1` 表示清单仍有待补证据或文件路径/哈希错误；这表示证据尚未齐备，不代表实验测量失败。结构无效或输入无法读取时返回码为 `2`。输入清单不会被修改。

项目现有 `preflight` 用于核对输入、几何、mask、校正声明和来源哈希，且明确不运行拟合；`annotation-pack` 用于生成盲化人工标注材料。二者可作为此协议的上游证据，但都不能单独证明测量误差、真实数据泛化或两名独立用户成功。只有在两组数据、重复测量、人工比较和两次用户会话都有可复核的原始记录后，才可据实更新论文中的结果与局限。
