# 批处理完整交付性能验证

性能范围是独立 Python 进程启动到 `batch --stream --report --package`
完成，包括输入身份验证、拟合、检查点、原生导出、报告所有图形格式及交付 ZIP。
报告生成或某个函数的计时不能代替这一范围。

## 可复现入口

在仓库根目录使用同一个 Python 环境、真实 manifest 和分析配置：

```powershell
& .\.venv-project\Scripts\python.exe scripts/benchmark_batch_delivery.py `
  --source <冻结源码目录> --manifest <manifest.json> --config <recipe.toml> `
  --output <全新结果目录> --revision <Git提交>
```

冻结目录需要包含 `src/butterfly_saxs`。可用 `git archive <提交> src`
分别生成基线和候选快照；不要在运行中修改快照。脚本记录实际源码、manifest、
配置的 SHA-256，避免仅凭 revision 标签认定运行版本。
原始图像、PONI 和 mask 只读，使用独立输出目录。

脚本为每次运行启动新进程，固定 Python 哈希种子、Agg 绘图及四种数值线程环境变量为 1。
基线和候选保持输入顺序、选择范围、配置、环境、报告格式和交付范围相同，串行交替运行。
新输出目录不代表操作系统文件缓存已清空；记录同机其他负载，不宣称冷磁盘性能。
`--profile` 只用于诊断，不能与无 profiler 的时间比较。

三种情形分别记录，不能混算加速比：

- 首次完整运行：全新输出目录，所有帧重新分析。
- 完整结果复用：对已完成的同版本输出加 `--resume`，仍验证输入、原生包、报告和 ZIP。
- 部分恢复：先用 `--stop-after N` 产生部分结果，再复制该输出作为两边相同的起点，
  使用 `--resume` 完成相同剩余帧及全部交付。比较版本必须具有相同的正确性修复。

退出码 1 可能表示保留科学质量警告或取消，必须读取 CLI JSON 的帧状态、完整性和交付状态。
不能把退出码 1 一律当作性能失败，也不能当作科学接受。
指标文件位于结果目录的相邻位置；拒绝覆盖已有指标，用 `--label` 保留额外重复测量。

## 数值和交付一致性

```powershell
& <包含numpy、Pillow和pypdf的Python> scripts/compare_batch_delivery.py `
  <基线结果目录> <候选结果目录> --output <新审计JSON>
```

审计检查文件清单、全部 NPZ 数组的键/形状/dtype/逐字节值（包括 NaN 位）、
CSV 与 JSON 科学值、PNG 像素、SVG 实际几何/嵌入图像和 PDF 解码后的绘图指令及资源。
只归一化运行耗时、恢复状态、生成时间、输出根目录、生产者指纹等运行差异；
科学方法版本仍检查。概览图若有图例布局差异，会单列，需额外人工确认；其它图像变化失败。
ZIP 全部成员读至 EOF 检查 CRC、SHA-256 及当前源文件一致性，并核对索引和 receipt 的完整元数据。
比较脚本版本和审计依赖版本也写入审计 JSON。独立审计时间与生产 CLI 时间分开列出。

Windows 的资源指标是进程 CPU 时间、峰值 working set 和逻辑读写字节；逻辑 I/O 包含
文件缓存访问，不等于物理磁盘流量。函数阶段计时包含嵌套调用，不应直接求和。

## 恢复与并发边界

计算恢复绑定输入内容、配置、分析入口、源码和依赖版本。报告、导出和 ZIP 还分别验证
自身生产者/设置、源内容和交付内容。有效文件版本仅在本次调用中用于复用已完成的验证；
无法取得可靠写入版本时重新读取内容。外部 analyzer 未提供稳定身份时不启用整包快速复用。

同一输出目录的 WingSAXS 写者使用操作系统文件锁，覆盖检查点、原生发布、报告和包装。
锁文件保留，进程退出由操作系统释放锁；不要按 PID 或文件年龄删除正在使用的锁。
不同目录可独立运行。取消续跑保留已有原生交付，已验证的检查点记录不会被未处理占位行抹掉。
检查点领先原生发布时，仅重算缺少可靠原生证据的帧。

`--hard-stop-after N` 是故障注入工具：在第 N 个持久化检查点后直接退出 99，
不运行 Python finally、不关闭暂存 ZIP、不发布新原生包。只对独立验证目录使用。
确认旧交付未改变、下一次续跑能重新取得锁并补齐缺少的帧；通过一致性审计后再清理该任务的孤立暂存目录。
这验证进程突然退出，不等价于断电时所有发布窗口的持久性证明。
非协作程序在任务运行时任意修改输出文件不属于输出锁的并发保证。

本协议不替代 P3/P4/R0 的科学验证；全量生产批次、其它输入格式、独立 full2d 模型及不同 Python/
操作系统必须有自己的运行证据，不能从一个真实六帧基准外推。
